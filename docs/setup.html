Reusable Field Service A2A Asset

Running the POC on your machine

A complete setup path for the CMTPlay My Day dashboard and the Property Upsell Agent, starting from an empty folder.

Time ~90 min, mostly Salesforce Second machine ~20 min Platform Windows / PowerShell

00What you are setting up

Two programs that run side by side in separate terminals. The app asks the agent for product recommendations over the A2A protocol, so the upsell feature does nothing unless both are running.

The app

Next.js dashboard and Copilot. Talks to Salesforce.

localhost:3000

The agent

Python service holding the product catalogue.

127.0.0.1:8001

Steps 1 to 4 can be done while you wait for Salesforce in step 5, which has a propagation delay of up to 30 minutes.

03Create a Gemini API key

The Copilot's reasoning runs on Gemini. The free tier is enough.

  1. Open aistudio.google.com/apikey
  2. Sign in with a Google account
  3. Create API key, then copy it somewhere safe

You will paste it into .env.local in step 6.

04Create an OpenRouter key

The agent's reasoning runs through OpenRouter, a router sitting in front of many model providers. You do not need to add credits.

  1. Sign up at openrouter.ai (Google or GitHub sign-in works)
  2. Go to openrouter.ai/keys
  3. Create Key, name it property-upsell-agent
  4. Copy the key. It starts sk-or-v1- and is shown only once

Two limits that will bite you

Free models only

With no credits on the account, any model without a :free suffix returns HTTP 402. Everything here is configured for :free models, so this is fine — but do not "helpfully" change the model id to a paid one.

50 requests per day, account-wide

The free tier allows 50 requests per day across all :free models combined, and each upsell question is one request. This is counted per account, so a team sharing one key shares the 50 between them.

Create your own key. A shared key runs out during rehearsal and the demo then fails with a provider error.

If a model starts refusing

Free models are throttled by whoever hosts them, separately from your account quota, so a model that worked yesterday can start returning 429 today. Three verified ids are listed in agent/.env.example; switch OPENROUTER_MODEL to another and restart the agent.

To tell the two causes apart, check your own quota:

Invoke-RestMethod -Uri "https://openrouter.ai/api/v1/key" `
  -Headers @{ Authorization = "Bearer sk-or-v1-YOUR-KEY" }

If free_model_daily_requests.remaining is above zero your account is fine and the model is the problem, so switch models. If it is zero, you are out until the quota resets.

05Configure Salesforce

The longest part. You need System Administrator access to a Salesforce org; a free Developer Edition org works.

5.1 — Activate the Hosted MCP server

Setup, search MCP, and activate platform/sobject-all for your org.

Most common failure

An inactive server lets OAuth succeed and then fails every call with 404 or 405. If you skip one check in this guide, do not skip this one.

5.2 — Create an External Client App

Setup → External Client App Manager → New External Client App. Enable OAuth, then set:

  • Callback URL — http://localhost:3000/api/auth/callback/salesforce, character for character, port included
  • Require Proof Key for Code Exchange (PKCE) — enabled
  • Enable Client Credentials Flow — not needed

5.3 — Select OAuth scopes

ScopeWhy
mcp_apiRequired. The generic api scope does not work with Hosted MCP
apiAlso required, for the dashboard's REST calls. Listed as Manage user data via APIs (api)
refresh_tokenAvoids repeating authorization
offline_accessRequested alongside the refresh token

Without api the dashboard fails with 401 INVALID_SCOPES while the Copilot still works — a confusing half-broken state that looks like a dashboard bug.

5.4 — Enable JWT-based access tokens

In the app's token settings, enable Issue JSON Web Token (JWT)-based access tokens. Without it OAuth appears to succeed and every MCP call fails with INVALID_AUTH_HEADER or INVALID_JWT_FORMAT.

Note

If the same app is also used for the SOAP API or the Salesforce CLI, create a separate app for those. They require opaque session-ID tokens and reject JWTs.

5.5 — Keep it a public client

Leave it as a public PKCE client and leave SALESFORCE_CLIENT_SECRET blank. Set a secret only if you deliberately made it a confidential client.

5.6 — Permit the user

Give the Salesforce user the app connects as:

  • Permission to use the MCP server, via a permission set
  • Exactly the object and field permissions the demo needs, and no more
This is the only access control

The app passes requests through and lets Salesforce accept or refuse them. If the demo must not write anything, make this user read-only here — there is no application-side block to fall back on.

5.7 — Copy the Consumer Key

From the app's OAuth settings. That value is your SALESFORCE_CLIENT_ID.

5.8 — Wait

A new External Client App can take up to 30 minutes to become usable. An immediate invalid_client_id usually just means "not ready yet".

06Configure the app

Copy-Item .env.example .env.local

Open .env.local and fill in:

GEMINI_API_KEY=<from step 3>
GEMINI_MODEL=gemini-flash-latest

SALESFORCE_CLIENT_ID=<Consumer Key from 5.7>
SALESFORCE_CLIENT_SECRET=
SALESFORCE_LOGIN_URL=https://login.salesforce.com
SALESFORCE_REDIRECT_URI=http://localhost:3000/api/auth/callback/salesforce
SALESFORCE_SCOPES=mcp_api,api,refresh_token,offline_access

SALESFORCE_MCP_URLS=https://api.salesforce.com/platform/mcp/v1/platform/sobject-all

A2A_UPSELL_AGENT_URL=http://127.0.0.1:8001

SETUP_SECRET=<generate below>

Generate the setup secret:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Pick the right MCP URL for your org type

Org typePath after https://api.salesforce.com/platform
Production / Developer Edition/mcp/v1/platform/sobject-all
Sandbox/mcp/v1/sandbox/platform/sobject-all
My Domain (required if login.salesforce.com is disabled)/mcp/v1/d/<mydomain>/platform/sobject-all

Using the production path against a sandbox fails to connect.

By design

A2A_UPSELL_AGENT_URL has no default. Leave it out and the Copilot says product recommendations are not configured, rather than failing against a localhost that would be dead on a deployed instance.

07Set up the agent

7.1 — Get the catalogue PDF

Not in the repository

The catalogue is excluded by policy. Ask the project owner for security_product_catalogue.pdf and put it in agent/catalog/.

The folder must hold exactly one PDF. With none or several, the agent refuses to start and says which, rather than guessing which to read. The PDF needs real extractable text — a scanned image will not work, as there is no OCR step.

7.2 — Install and configure

cd agent
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env

Open agent/.env and set your key:

OPENROUTER_API_KEY=<from step 4>

Leave OPENROUTER_MODEL alone — it already names a verified working model.

7.3 — Start it

.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8001

A banner confirms what it loaded:

[Property Upsell Agent] ready
  catalogue : security_product_catalogue.pdf (1 pages, 2,431 chars)
  provider  : openrouter
  model     : openrouter/nvidia/nemotron-3.5-lightning:free
  agent card: http://127.0.0.1:8001/.well-known/agent-card.json

Leave this terminal open. The agent runs in the foreground.

Verify the card from a second terminal:

Invoke-RestMethod http://127.0.0.1:8001/.well-known/agent-card.json |
  ConvertTo-Json -Depth 5

It must publish a skill with id property_upsell_recommendations — that is what the app matches on.

08Authorize Salesforce

In a new terminal, from the repository root:

npm run dev
Expect this

The first start stops itself with a Next.js security advisory saying "Retry the same command to continue." Run npm run dev again and it stays up. This happens on every cold start, including npm run build.

Then open this once in a browser, using your real SETUP_SECRET:

http://localhost:3000/api/auth/salesforce?secret=<SETUP_SECRET>

Log in as the Salesforce user and approve. Tokens are written to .local/, which is git-ignored. You do this once.

09Map a technician

The dashboard shows nothing until a technician ID is mapped to a Salesforce ServiceResource.

9.1 — Find the ServiceResource Id

Developer Console → Query Editor:

SELECT Id, Name, RelatedRecordId, IsActive
FROM ServiceResource
WHERE IsActive = true

Note the Id (starts 0Hn) and the Name. You need both — the name matters in step 10.

9.2 — Add the mapping

In .env.local:

CMTPlay_DEMO_MODE=true
CMTPlay_TECHNICIAN_DIRECTORY=[{"technicianId":"TCH-7842","serviceResourceId":"0Hn..."}]

The technician ID is yours to choose. There is no password — anyone signing in with a mapped ID sees that technician's jobs, which is acceptable for a controlled POC only.

9.3 — Check how your org links jobs

Appointments reach a technician one of two ways and the default assumes AssignedResource. Check yours: 

SELECT COUNT() FROM AssignedResource WHERE ServiceResourceId = '0Hn...'

If that returns 0 but the resource clearly has jobs, your org links them by Owner instead. Add: 

CMTPlay_APPOINTMENT_SOURCE=owner_query

Without this the dashboard is empty, you never open a job, and you never reach the Upsell tab. Restart npm run dev after editing .env.local.

10Run the demo

  1. Open localhost:3000/my-day
  2. Sign in
  3. Click a job in the timeline
  4. Open the Upsell tab
  5. Click Recommend upsell products
Sign in with the matching name

The technician ID scopes the dashboard. The Copilot looks appointments up by the name you type. If the name does not match the ServiceResource's name in Salesforce, upsell fails with "SA-nnnn was not found in the technician's schedule" and nothing is recommended.

That is correct behaviour — it refuses to guess a property — but it looks like a bug in front of an audience. Use the Name from step 9.1.

You should see two progress lines, then recommendations with a catalogue page cited for each product.

Timing

A delegated turn takes 50-60 seconds, because one turn runs the whole catalogue through the agent's model. The timeout is 180s. Do not click twice — each click spends one of your 50 daily requests.

Checking both halves are alive

Invoke-RestMethod http://localhost:3000/api/config
Invoke-RestMethod http://127.0.0.1:8001/.well-known/agent-card.json

The first returns a Copilot mode, the second the agent card. If either fails, that half is down.

13Pre-demo checklist

  • Agent terminal open, banner showing the catalogue and model
  • App terminal open, survived the advisory retry
  • Agent card returns the property_upsell_recommendations skill
  • Signed in with the name matching the ServiceResource
  • Dashboard shows today's jobs
  • One upsell run completed today, so nothing is cold
  • OpenRouter quota checked — enough of the 50 left for the session
